## 2026-05-20 (Sprint 2 Day 3)

### 今日学んだこと

- **React Hook Form と Zod Resolver の関係**
  - `useForm<BookFormInput>()` で型チェック
  - `{ resolver: zodResolver(bookFormSchema) }` で Zod がバリデーションを引き受ける
  - `register` のオプション（`required` など）は resolver があると無視される
  - エラーメッセージは全て `bookFormSchema` から来る

- **`setValueAs` でテキスト入力を配列に変換**
  - `<input>` は常に文字列を返す
  - `setValueAs: (v) => v.split(",").map(s => s.trim()).filter(Boolean)` でカンマ区切り文字列を配列に
  - `authors` と `tags` で使用

- **`valueAsNumber` で文字列を数値に変換**
  - `<input type="number">` もデフォルトは文字列型
  - `register("pages", { valueAsNumber: true })` で自動変換

- **`z.preprocess()` で値を加工してからバリデーション**
  - HTML フォームの `<input>` は何も入力しない場合 `""` を返す（`undefined` ではない）
  - `.optional()` は `undefined` だけを許可。`""` は許可しない
  - `z.preprocess((v) => v === "" ? undefined : v, z.string().regex(...).optional())` で解決

- **`Omit<Book, 'id' | 'createdAt'>` の設計**
  - `id` と `createdAt` はサーバー生成（またはコード生成）
  - フォームでは受け取らない → `bookFormSchema.omit({ id: true, createdAt: true })`
  - `z.infer<typeof bookFormSchema>` で `BookFormInput` 型を自動生成

- **スプレッド構文 `...data` でオブジェクトを組み立て**
  - `const newBook: Book = { ...data, id: crypto.randomUUID(), createdAt: new Date().toISOString() }`
  - `data` は `BookFormInput`、これに2つのフィールドを足して `Book` 完成

- **VS Code の import パス設定**
  - `"typescript.preferences.importModuleSpecifier": "non-relative"` で `@/` 優先
  - 相対パスから自動インポート時に `@/schemas/book` 形式になる

### 詰まったこと

- **スキーマと bookData の型ズレ**
  - `author` (単数) vs `authors` (複数) の名前ズレで型エラー
  - `publishedYear`・`status`・`createdAt` がスキーマにはあるが bookData にはない
  - 解決: bookData 全30件に足りないフィールドを追加

- **`register("bookForm.title")` の誤解**
  - `useForm` に `Props` 型を渡していた（ネストされた props に対応する表記）
  - 正しくは `useForm<BookFormInput>()` → `register("title")` とフラット

- **`errors &&` は常に true**
  - `errors` オブジェクト自体は常に存在（エラーなし時は `{}`）
  - 正しくは `errors.title &&` で特定フィールドをチェック

- **optional フィールドで空文字バリデーション失敗**
  - `z.preprocess()` がなく `""` のまま regex に渡されていた
  - `.optional()` だけでは解決しない → `z.preprocess()` で `""` → `undefined` に変換

### 設計で考えたこと

```
BookFormInput の必要性:
- Book 型をそのままフォームに使うと、id と createdAt の入力欄が出来てしまう
- Omit でそれらを除いた型を作ることでコンポーネント層を明確に
- フォーム入力 → BookFormInput → id/createdAt 追加 → Book → localStorage
という流れが型で保証される
```
