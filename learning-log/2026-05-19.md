## 2026-05-19 (Sprint 2 Day 2)

### 今日学んだこと
- TypeScriptの型チェックはコンパイル時だけ。`as Book` は「信じる」宣言で中身を保証しない
- Zodはランタイム（実行時）にデータを検証する。外から来るデータ（localStorage・API・フォーム）に使う
- `safeParse` は失敗時に例外を投げず `{ success: false, error: ... }` を返す。`parse` は例外を投げる
- `z.infer<typeof bookSchema>` でスキーマから型を自動生成できる。型定義とスキーマが一か所にまとまる
- `z.enum([...])` でリテラルUnion型を表現できる
- `z.array(z.string()).refine(...)` の重複チェックは配列レベルに書く。要素レベルに書くと文字の重複チェックになってしまう
- Zod v4では `.url()` → `z.string().check(z.url())`、`.datetime()` → `z.iso.datetime()` に変更された
- Hooksはコンポーネント関数のトップレベルでしか呼べない。`if` の中に `useState` を書くとReactがエラーを出す

### 詰まったこと
- `refine` の引数を誤解していた → `z.array(...).refine(items => ...)` の `items` は配列全体。要素レベルの `refine` の引数は文字列1個
- `bookSchema.safeParse(schema)` と引数を逆に書いた → 正しくは `schema.safeParse(データ)`
- `useLocalStorage` に `schema` を渡し忘れてランタイムエラー → 呼び出し側の引数漏れ
- `bookSchema`（Book 1件）を `Book[]` の検証に使っていた → `z.array(bookSchema)` でラップする必要がある

### 今日実装したこと
- `src/schemas/book.ts` 作成
  - 全フィールドをZodスキーマで定義（型だけでなくバリデーションルールも）
  - `z.infer<typeof bookSchema>` で `Book` 型を生成
  - 追加した制約: pages は1以上の整数、publishedYear は1900〜2027、ISBNは10桁か13桁の正規表現、tagsは重複禁止
- `src/hooks/useLocalStorage.tsx` にZod検証を組み込む
  - `schema: z.ZodType<T>` を第3引数として受け取る
  - `useState` の初期化関数内で `safeParse` を実行
  - 検証失敗時は `initialValue` にフォールバック

### 設計で考えたこと（schema をオプショナルにするか）
```
必須にした理由:
- オプショナルにすると schema がない時に as T に戻り、Zodを導入した意味がなくなる
- このプロジェクトでは常に bookSchema があるので optional にする理由がない
- シンプルな設計を優先した
```

### Zodが解決する3つのシナリオ
| シナリオ | TypeScriptだけの問題 |
|---|---|
| localStorage | `as Book` で嘘をつける。壊れたデータに気づけない |
| フォーム入力 | バリデーションルールと型定義が別々になりがち |
| 外部API | レスポンスのフィールド変更に気づけない |
