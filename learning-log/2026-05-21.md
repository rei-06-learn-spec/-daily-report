## 2026-05-21 (Sprint 2 Day 4)

### 今日学んだこと

- **Discriminated Union でコンポーネントの Props を型安全に分岐する**
  - `mode: 'create' | 'edit'` という単純な union では、`edit` 時に必要な `defaultValues` が `create` 時にも型として現れてしまう
  - Discriminated Union を使うと `mode` の値によって型そのものが切り替わる
  ```typescript
  type Props =
    | { mode: 'create'; onSubmit: (data: BookFormInput) => void }
    | { mode: 'edit';   onSubmit: (data: BookFormInput) => void; defaultValues: BookFormInput };
  ```
  - `mode: 'edit'` のとき `defaultValues` は**必須**、`mode: 'create'` のときは**存在しない**ことが型で保証される

- **分割代入すると Discriminated Union の絞り込みが失われる**
  - `const { mode, defaultValues } = props` と書くと TypeScript は型の分岐を追えなくなる
  - `props` を丸ごと受け取り `props.mode === 'edit'` で絞り込むと、その後 `props.defaultValues` に安全にアクセスできる（型の narrowing）

- **`useForm` の `defaultValues` で初期値を流し込む**
  ```typescript
  useForm<BookFormInput>({
    resolver: zodResolver(bookFormSchema),
    defaultValues: props.mode === 'edit' ? props.defaultValues : undefined,
  });
  ```
  - `mode` で条件分岐して渡すだけでフォームに初期値が入る

- **`setValueAs` は `defaultValues` の適用時にも実行される**
  - `setValueAs` は「ユーザーが入力したとき」だけでなく、初期値セット時にも走る
  - 編集時に `defaultValues.authors` はすでに配列なのに `.split()` を呼ぼうとしてクラッシュ
  - `Array.isArray(v)` でガードして配列ならそのまま返す
  ```typescript
  setValueAs: (v: string | string[]) => {
    if (Array.isArray(v)) return v;
    return v.split(",").map((s) => s.trim()).filter(Boolean);
  }
  ```

- **`map` で配列の特定要素を差し替えるパターン**
  - `filter` が条件に合わないものを**削除**するのに対し、`map` は全要素を**変換**して新しい配列を返す
  - id が一致する要素だけ新しいオブジェクトに差し替え、それ以外はそのまま返す
  ```typescript
  books.map((b) => b.id === book.id ? book : b)
  ```

- **ページコンポーネントはURLを介して疎結合にする**
  - 編集ページへの遷移で「親から props を渡す」のではなく、URL の `:id` から自分でデータを取得する
  - ページを直接開いたとき・リロードしたときも動く設計になる
  - 親は `navigate('/books/:id/edit')` でURLを変えるだけ、データの受け渡し不要

### 詰まったこと

- **`editBook` を関数ではなく配列として定義してしまった**
  - `const editBook = books.map(...)` と書いてしまい、関数ではなく結果（配列）が代入された
  - `addBook` と同じく `const editBook = (book: Book) => setBooks(books.map(...))` が正しい形

- **`map` の中で `return;`（undefined）を返していた**
  - 一致しない要素を返し忘れて `return;` にしていた → 配列に `undefined` が混入して型エラー
  - 「一致する → 新しい値を return」「一致しない → 元の値を return」の両方が必要

- **`map` の中で古い値（`b`）を返していた**
  - 差し替えたいのに `return b` と書いていた → 何も変わらないバグ
  - 一致したときに返すのは `book`（新しい値）、一致しないときが `b`（元のまま）

### 設計で考えたこと

```
編集フォームのデータの流れ:
URL(:id) → useParams → books.find → article(Book型)
  ↓
article を defaultValues として BookForm に渡す（Book は BookFormInput の上位集合なので型互換）
  ↓
フォーム送信 → BookFormInput を受け取る
  ↓
{ ...data, id: article.id, createdAt: article.createdAt } で Book に復元
  ↓
editBook で books 配列の該当要素を差し替え → localStorage 更新
```
